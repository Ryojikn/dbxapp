## Summary

Build a three-tab Dash web application that presents an end-to-end Databricks data platform demo — Home orientation, interactive architecture diagram, and a live analytics dashboard with embedded chat — deployable as a Databricks App from a clean clone in under 30 minutes. All data is fixture-based; the chat panel uses keyword matching with an optional Databricks Model Serving passthrough. See [research.md](research.md) for framework evaluation and [data-model.md](data-model.md) for entity definitions.

---

## Technical Context

**Language/Version**: Python 3.10+  
**Primary Dependencies**: Dash 2.17, Dash Bootstrap Components 1.6, dash_cytoscape 1.0.2, Plotly 5.22, pandas 2.2, requests 2.31  
**Storage**: None — all data is in-memory Python objects defined in `data/` module  
**Testing**: pytest + dash[testing] (Selenium-based integration tests for tab switching and chat callbacks)  
**Target Platform**: Databricks Apps (Linux, serverless Python runtime); local dev on macOS/Linux  
**Project Type**: Web application (single-page, multi-tab)  
**Performance Goals**: Tab switch < 100ms perceived; chart render < 500ms; chat keyword response < 50ms; LLM proxy response < 10s (with timeout fallback)  
**Constraints**: Zero external service calls required for demo path; all diagram assets bundled; no CDN dependency; app must start with `python app.py` and read `PORT` from env  
**Scale/Scope**: Single presenter session; no concurrent-user scaling required; ~15 source files; < 1000 lines of Python

```text
└── custom.css            ← Node color palette, KPI card borders, chat bubble styles

tests/
├── test_fixtures.py      ← Unit tests: fixture integrity (1 anomaly, 360 rows, KPI math)
├── test_chat.py          ← Unit tests: keyword matching, template rendering, fallback
├── test_architecture.py  ← Unit tests: node/edge counts, all node IDs valid
└── test_app.py           ← Integration: tab switching, chart render, chat interaction
```

**Structure Decision**: Single-project Python layout. `data/` is the pure-Python data layer (no Dash imports). `components/` contains layout functions that return Dash component trees. `callbacks.py` wires all interactivity. `app.py` assembles and runs. This separation keeps data fixtures independently unit-testable without spinning up a Dash server.

## Implementation Phases

### Phase A — Scaffold and Data Layer

1. Create project scaffold (all files/dirs, empty modules, requirements.txt, app.yaml)
2. Implement `data/fixtures.py`: 360-row SalesRecord list, KPISummary computation, DataFrame factory
3. Implement `data/architecture.py`: 13 nodes, 14 edges, Cytoscape element builder
4. Implement `data/chat.py`: 5 ChatRules, `match_rule()`, `render_response()`
5. Write unit tests for all three data modules
6. Verify: `pytest tests/test_fixtures.py tests/test_chat.py tests/test_architecture.py` all pass

### Phase B — Layout Components

7. Implement `components/home_tab.py`: hero section, 3 preview cards with navigation links, metadata row
8. Implement `components/architecture_tab.py`: `cyto.Cytoscape` with dagre layout, stylesheet, detail panel `html.Div`
9. Implement `components/dashboard_tab.py`: KPI row (4 `dbc.Card`), trend chart (`dcc.Graph`), category chart (`dcc.Graph`), anomaly table (`dash_table.DataTable`), chat panel (`html.Div` + `dcc.Input` + send button)
10. Implement `app.py`: DBC layout shell, `dbc.Tabs` with three `dbc.Tab` children, `dcc.Store` components

### Phase C — Callbacks and Interactivity

11. Implement `callbacks.py`:
    - Tab content routing (if using `dcc.Tabs` + dynamic content pattern)
    - Architecture node hover → detail panel update
    - Dashboard chart filter → chart trace update
    - Chat submit → `match_rule` → `render_response` → history append
    - (Optional) Chat submit → Model Serving proxy when env vars present
12. Implement `assets/custom.css`: node category colors, KPI card left-border styling, chat bubble styles

### Phase D — Deployment and Verification

13. Write `app.yaml` and verify `PORT` env var handling in `app.py`
14. Write `README.md` following the quickstart guide
15. Run full integration test suite
16. Deploy to Databricks Apps; walk the rehearsed demo path (quickstart Step 5)
